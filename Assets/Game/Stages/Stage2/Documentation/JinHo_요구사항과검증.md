# JinHo 요구사항과 검증 상태

2026-10-30. 현재 구현과 요구사항은 구분한다. 새 요구나 최신 확정이 과거 계산/문서보다 우선한다.

## 유지할 요구사항

- 기준 ManorPrototype의 시작 구역·Player 시작 위치/방향·문1·열쇠1·기존 탈출 대상의 원본 동일성을 보존한다. 지정된 맵 배치·소리/경비 예외 외에는 원래 조작·HUD·인벤토리·미션·성공/실패·재시작을 재사용한다.
- 원본 평면도의 공간 역할·연결을 따르고 Top 기준 180도 방향을 적용한다. 시작 구역은 유지한다. 초기 2배 확대 이후 사용자 수동 치수 조정이 있으므로 전 구역이 정확히 2배라고 주장하지 않는다.
- 보물방은 문2 단일 출입이다. 획득 후 같은 문2로 중앙 통로에 나와 중앙 하단 열린 길로 오른쪽에 진입한다. 보물방 옆 출구는 없다. 보물방에 전신 진입한 뒤 획득해야 한다.
- 첫 유인 관찰 후 약 1초 대기와 별도로 문2/보물 조작에 약 2초 여유를 둔다. G1 몸 앞부분이 C에 들어오기 전에 보물을 가진 채 S에 도착하고, S에서 10초 정지해도 발견되지 않아야 한다. C는 중앙 복귀 경계, S는 보물 획득 후 안전 대기 지점으로 사용한 설계 표식이다. 현재 좌표와 실제 안전 여부는 전체 동선 검증이 필요하다.
- 오른쪽 단계는 G2 전신 입장 확인 후 약 1초 대기/이동 여유를 고려한다. 입장 순서 G1→G2, 퇴장 순서 G2→G1과 각각 최소 0.5초 간격을 검사한다. 개별 대기 3초보다 역순 유지가 우선한다.
- 유인1 최신 추가 유지 시간은 2초다. 출력 종료 기준이며 방 전신 입장 기준 2초 체류로 바뀐 것은 아니다. 원본 출력/경계 시간을 유지한다.
- 거울은 플레이어가 문3에 가기 전에 G2를 확인하기 위한 것이다. 단일 관찰 틈도 플레이어 관찰과 비발견을 함께 만족해야 한다. 서기 기준이며 경비에게 보이지 않는 조건을 우선한다.
- 문4 자체 개폐음은 원본을 유지한다. 그 자체음에 대한 G1 필수 반응은 요구하지 않으며 G2 신규 반응을 만들지 않는다. 장치에 주입한 2등급 출력과 문 자체음은 구분한다.
- 기존 소리 추출 대상의 종류·구성·조건과 원래 복귀/R 재시작을 보존한다. 별도 순찰/방 확인 동선이나 안전 재시도 보장은 요구하지 않는다.

## 실제 확인한 결과

소리방 폭 5.423265 조정 후 실행한 두 번의 Play 검사 결과다. 이후 유인1 2초/주석 변경과 이번 파일 정리는 별도 Play 검사를 하지 않았다.

| 실행 | 결과 | 해석 |
| --- | --- | --- |
| 1. 공통 SoundThief.Tests | 38/38 통과 | 당시 공통 회귀 검사 통과. 전체 JinHo 동선 합격을 뜻하지 않음 |
| 2. JinHoCurrentRevisionTests | 2/4 통과 | 유인1 추가3초 당시 검사와 두꺼운 벽/서기 틈 검사 통과 |
| 같은 실행의 거울 검사 | 실패 | 반사 렌더 42회, 직접 시야 차단 확인. 반사 경로가 막힘 |
| 같은 실행의 유인2 검사 | 실패 | G2 전신 입장 약 5.240초 기록, 플레이어 발견/체포. G1 입장·역순 퇴장 완료 확인 실패 |

당시 유인1은 출력 종료 8.003초, 전신 입장 8.417초, 복귀 시작 15.016초였다. 이는 추가3초의 과거 결과이며 **현재 추가2초 결과가 아니다**.

체포 뒤 원래 Restart가 호출됐으나 당시 활성 전용 프로필에 JinHo 씬이 없어 씬 로드 오류가 발생했다. 이번 정리에서 전용 프로필에 현재 씬을 넣고 폐기/중복 항목을 제거했다. 이 수정 후 실제 Restart는 아직 미검증이다. 공유 미션 코드는 바꾸지 않았다.

기능 검사는 관찰 위치 준비와 원래 공개 소리 API를 사용한 제한된 검사다. 정상 입력으로 Q 이후 실제 이동해 관찰하는 전체 동선이나 맵의 모든 지점에 대한 증명이 아니다. 과거 배치의 검사 결과는 현재 배치로 일반화하지 않는다.

## 남은 검증

사용자 후속 확인: 직접 플레이에서는 거울 차폐와 유인2 발견 문제가 없다고 보고했다. 위 자동 검사 결과는 준비된 관찰점과 당시 실행 조건의 과거 기록이며, 현재 플레이에서 재현되는 결함으로 단정하지 않는다. 사용자 확인과 별개로 입퇴장 시간·간격, 현재 추가2초 유인1의 조작 여유, C/S 조건, 몸 전체 통과, 정상 전체 동선·성공/실패/R, 실제 스피커 청취, 임의 재주입의 정량 검증은 완료 처리하지 않는다.

사용자의 새 보고는 거울 앞에서 자기 모습이 보이지 않는 것이다. Editor 읽기 전용 조사에서 PlayerRig와 First person view만 있고 자식 Renderer는0개였다. 원본 ThiefPlayer는 소리 연결용 LineRenderer를 런타임에 만들지만 몸 모델을 생성하지 않는다. 몸 표시가 없으므로 자기 신체를 반사할 수 없는 상태다. 몸 모델 또는 거울 전용 외형 추가는 이번에 수행하지 않았고 Player/카메라/씬은 변경하지 않았다. 추가 Play 테스트도 실행하지 않았다.

정리 후 컴파일·참조 검사와 Play/전체 동선 검사는 구분해 [push 준비 기록](JinHo_push준비.md)에 기록한다. 알려진 실패를 숨기려고 테스트를 삭제하거나 기대값을 통과하게 완화하지 않는다. 현재 맵 테스트의 두 실패 시나리오는 유지했다.
