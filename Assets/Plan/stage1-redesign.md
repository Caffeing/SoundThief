# 스테이지 1 저택 구조 개선 개발문서

2026-10-29 · 대상: `Assets/Scenes/ManorPrototype.unity` · 상태: 사용자 피드백에 따라 핵심 플레이 구조 재설계 필요. 기존 구현·자동 검증은 아래 개발 이력이며 재미 검증 완료를 뜻하지 않는다. 최신 진단과 제안: `stage1-core-loop-rework.md`.

## 방향

기존 단일 홀 중심 그레이박스를 확장해 현관·중앙 홀·서재·식당·인장 보관 공간을 연결한다. 사용자가 선택한 두 방은 **서재와 식당**이다. 길드·연습장 제작은 이번 범위에 포함하지 않는다.

현관에서 열쇠를 얻고 정문을 지나 중앙 홀에 진입한다. **서재에서 식당 열쇠를 확보한 뒤 잠긴 식당에 들어가 인장을 얻고 현관으로 탈출**한다. 사용자가 두 방 모두 위험과 보상이 있고, 한 방의 선행 행동이 다음 방 진입을 열어주길 원했다. 소리 주입 완료 자체를 의뢰 성공 조건으로 만들지는 않는다.

## 공간과 상호작용

- 현관: 시작 위치, 열쇠, 기존 잠긴 문과 탈출 출구. 기존 열쇠·자물쇠 소리 관계를 유지한다.
- 중앙 홀: 긴 시야와 경비, 기둥·가림막을 배치해 직행과 측면 우회가 갈리는 공간.
- 서재: 책장·책상·시계·경비와 식당 열쇠. 책장은 가림막 역할을 하고 시계는 소리 주입과 관계 추출이 가능한 대상이다. 두 출입구를 통해 홀로 돌아갈 수 있다.
- 식당: 앞문과 뒷문 모두 식당 열쇠가 필요하다. 긴 식탁·의자·갑옷 장식·경비와 인장을 배치한다. 갑옷은 소리 주입 대상이며 인장 획득 후 두 문 중 하나와 홀을 지나 현관으로 되돌아간다.
- 중앙 홀 후방: 가림막과 연결 공간. 인장은 식당으로 옮긴다.

## 중간 검토 — 현재 사진과 개선 과제

사진 초안은 현관에서 중앙 홀을 거쳐 좌우 방으로 우회한 뒤 후방 인장을 회수하는 기본 흐름을 빠르게 확인하기 위해 대칭으로 배치했다. 검토 결과, 두 방이 비슷한 역할을 하고 위험을 감수할 동기가 부족하다. 소리 운반의 느린 이동·등급별 기한도 길어진 거리에 영향을 준다. 실제 경비 반응·왕복 시간으로 조정해야 하며 자동 검사 통과만으로 재미를 확정하지 않는다.

사용자 답변: 두 방 모두 위험과 보상이 있어야 하며, 한 방에서 선행 행동을 해야 다음 방에 갈 수 있도록 한다. 서재의 식당 열쇠가 식당 문을 열고, 식당에서 인장을 얻는 선형 의뢰 구조로 구체화한다. 서재와 식당의 경비 배치는 잠입·유인 선택을 제공하도록 한다. 실제 플레이에서 경비가 열쇠·문을 막거나 지나치게 쉽게 지나칠 경우 조정한다.

두 번째 사진에 대한 사용자 피드백: 방 모양을 더 다채롭게 하고 크기를 키운다. 서재는 후방 외곽에 이어지는 ㄱ자 형태의 별도 서가 공간을 추가하고 식당은 전방 외곽으로 확장된 공간을 추가한다. 식당 열쇠와 인장을 각각 확장부에 배치해 넓어진 공간에 들어갈 이유를 만든다. 기존 현관→서재→식당→탈출 선행 조건은 유지한다.

기존 청록색 공명체는 레벨의 갑옷·시계로 교체한다. 공통 SoundRelation/SoundEmitter를 사용해 기존 추출·주입·복구 규칙을 유지하고, 조준 시 물건 이름과 관계를 보여준다. 초기 실루엣용 도형은 후속 환경 아트 작업에서 시계·갑옷 에셋으로 교체했다. 최신 외형 기준은 stage1-environment-art.md를 따른다. 투척은 계속 비활성이다.

문에도 소리를 주입할 수 있다. 주입한 소리는 3초 대기한 뒤 출력되며 출력 시간과 감쇠는 재생 시작부터 계산한다. 대기 중에도 해당 대상은 사용 중이고 원래 소리 관계는 출력 종료 시 복구된다.

## 에셋 적용 작업

Creator Bundle의 Slavica와 Harboria에서 필요한 모델을 선택해 사용한다. 서재의 책장, 식당의 식탁·의자, 현관과 식당 문, 중앙 홀 기둥, 책·촛불·랜턴을 적용한다. 기존 충돌과 의뢰 진행은 유지하며, 원래 모델은 충돌 용도로 남긴다. 플레이 화면에서 크기·재질·상호작용을 검증한 뒤 조정한다. Harboria 건축물과 Cute Dungeon 소품 등 추가 후보를 검토하며, 문·시계·갑옷과 열쇠는 기능과 식별성을 우선한다. 씬의 기존 기하 구조를 대체하는 변경은 문과 복도의 통과 가능성 및 경비 이동을 함께 검증한다.

실내 프리뷰에서 천장이 없는 문제와 문 모델 방향 오류를 발견해 천장·보·따뜻한 조명을 추가하고 문의 방향을 고쳤다. Cute Dungeon에서는 열쇠 모델, 갑옷 옆 방패와 식당의 잔·접시를 적용했다. 시계는 나무와 황동 장식을, 갑옷은 금속 판과 어깨 장식을 추가한 제작 중인 모델이다. 경비는 Slavica 인물에 대기·걷기 애니메이션을 연결한 임시 외형이며 전용 경비 복장은 아니다. 모델 교체 후 실제 화면과 의뢰 진행을 재검증해야 한다.

벽의 목재 몰딩은 충돌이 없는 장식으로 추가하고 하나의 메시로 묶었다. 도보 자동 검증은 경비를 끈 상태에서 캐릭터 충돌과 실제 조준을 사용하여 출발점부터 두 열쇠·인장·출구를 연결한다. 문을 연 뒤 길찾기 갱신을 기다린 검사에서 통과했다. 경비를 켠 상태의 수동 플레이와 잠입 난이도는 별도로 검증해야 한다.

톤앤매너 조정: 서재 책장은 긴 모델을 늘리는 대신 원래 비율에 가까운 책장 여덟 개로 구성하고 선반 높이에 책을 채웠다. 식당은 탁자에 맞춘 의자와 잔·접시·병을 배치하고 서재 책상을 실제 가구로 교체했다. 벽·바닥·카펫은 따뜻하고 차분한 색으로 맞췄으며, 가구의 원래 충돌체와 통로는 유지한다. 추가 식기와 책은 장식으로서 충돌을 생성하지 않는다.

이전 배치에서는 경비 활성 전체 귀환 시도 중 홀과 식당 앞문 부근에서 경비에 잡혔다. 이를 개선하기 위해 서재 열쇠를 동일하게 요구하는 식당 뒷문을 추가했다. 최신 전체 PlayMode 검사 27개가 통과했으며 결과는 `stage1-asset-pass-test-results.json`에 기록한다. 두 식당 문의 잠금 및 열림 시 모델 정렬, 경비 활성 뒷문 귀환을 포함한다.

중앙 홀의 사각 가림막은 크기가 다른 장식장 두 개와 책으로 보강했다. 가림막의 원래 충돌·시야 차단은 유지한다. 식당 앞문·뒷문은 같은 목재 모델을 사용하며 물리적인 문짝과 열림 방향이 맞도록 정렬한다.

천장 아래의 주요 조명 다섯 곳에는 Slavica 랜턴과 매달린 줄을 배치했다. 랜턴은 충돌 없는 장식이며, 적용 후 실제 게임 화면과 기존 두 열쇠·인장·출구 상호작용 검사를 다시 확인했다. 에셋 출처와 용도는 `stage1-asset-sources.md`를 따른다.

던전 팩의 여러 바닥 후보를 비교해 저택과 어울리는 어두운 목재를 선택했다. 2m 부품을 시각용 메시로 합쳐 기존 바닥의 화면 겹침을 없애고, 기존 충돌과 경비 길찾기 데이터는 그대로 유지한다. 적용 후 두 열쇠·인장·출구까지의 충돌 기반 도보 검사도 통과했다. 반복 배치된 서재·홀 책은 공간별 메시로 합쳤고 원본 배치는 비활성 상태로 보존했다.

최종 실행 화면 기록: `Images/stage1-final-study.png`, `Images/stage1-final-dining.png`, `Images/stage1-final-hall.png`, `Images/stage1-dining-rear-door.png`. 장면은 저장되어 있고 편집 모드로 돌아왔다. 키보드 직접 완주와 사용자 체감에 따른 난이도·미술 조정은 자동 검증 결과에 포함하지 않는다.

뒷문 추가 뒤 경비 3명을 활성화한 자동 시나리오에서 무음 정문·시계 유인·서재 열쇠·무음 식당 앞문·갑옷 유인·인장·무음 식당 뒷문을 거쳐 현관까지 이동하는 경로가 통과했다. 운반 중 낮아진 시점, 실제 운반 속도와 남은 시간도 확인한다. 이 시나리오는 키보드를 직접 조작하는 수동 플레이가 아니므로 체감 난이도와 미술 방향은 별도로 확인해야 한다.

경비를 켠 실제 속도 자동 시나리오에서 정문 소리를 추출해 무음으로 열고, 운반해 시계에 주입한 뒤 서재 경비를 유인하고 후퇴하는 단계는 통과했다. 뒤쪽 출입구 접근 전 경비가 시계 쪽으로 이동할 시간을 주면 서재 열쇠와 식당 인장까지 회수할 수 있었다. 식당 갑옷 소리는 현행 청각 규칙에서 벽을 통과해 홀 경비도 깨우며, 이전에 시도한 앞문 귀환 경로는 경비에게 차단됐다. 새 식당 뒷문을 통한 경비 활성 자동 완주는 성공했다. 테스트는 게임 입력 대신 실제 속도의 CharacterController 이동과 조준을 사용하고 능력 타이머를 별도로 확인한다.

## 구현과 확인

현재 씬과 사용자 변경을 먼저 확인하고 원본을 보존한 뒤 씬을 개편한다. 방 외곽·출입구·가구 충돌, 실제 이동 가능한 공간, 플레이어의 시작과 탈출, 경비 NavMesh와 문 장애물을 확인한다. 공통 시스템이나 다른 팀원의 씬을 변경하지 않는다. 저택의 기존 검사와 새 동선·대상 기능 검사를 실행하며, 실제 Game 화면도 확인한다.

**후속 구현 반영:** 벽·문에 따른 청각 감쇠와 순간음·지속음 조사 분리는 2026-10-29~30 잠입 개선에서 구현했다. 현재 순찰·두 유인 경로·인장 소음·자동 닫힘과 검증은 stage1-core-loop-rework.md를 따른다.
