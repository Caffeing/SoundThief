# 빌드 입력·발소리·에셋 참조 수정

## 원인과 수정

- 빌드에서 `ThiefPlayer.Awake()`가 런타임 `Shader.Find` 결과로 재질을 만들다가 예외가 발생해 입력 초기화가 중단됐다. `Resources/SoundConnection` 재질을 직접 포함하고 복제하도록 변경했다. 같은 방식으로 소리 링과 스테이지 2의 거울 파편 재질도 보강했다.
- 씬마다 저장된 플레이어 발소리 음량과 스캔 밝기가 달랐다. 길드·스테이지 2·우편 스테이지의 기본 음량을 걷기 0.3, 앉기 0.1, 소리 운반 0.2로 맞췄고 스캔 밝기는 0.22로 맞췄다. 씬별 발소리 클립 선택은 유지한다.
- 자기 발소리는 플레이어에게 직접 들리는 소리이므로 방별 외부 소리 정책 때문에 스캔이 사라지지 않도록 분리했다. 다른 소리의 스캔 전파는 스테이지의 위치 기반 청각 정책을 따른다.
- 플레이어 발소리 스캔은 경비병 기본 발소리 범위의 1/3이며 앉으면 그 절반이다. 발소리 재생 이벤트 하나에서 파동도 함께 발생한다.
- 씬 NavMesh 등록 전에 경비병 에이전트가 활성화되는 경고를 줄이도록 에이전트 활성화를 Start로 미뤘다. 원래 비활성화된 경비병은 자동 활성화하지 않는다.
- 필수 플레이어 연결·발소리 파일·게임 재질이 빠지면 빌드를 중단하고 해당 씬을 알리는 검사를 추가했다.

## 에셋 조사

실제 게임과 공통 리소스의 의존성을 조사했다. 파티클 텍스처는 현재 셰이더에 정상 연결되어 있었다. 옛 셰이더의 사용하지 않는 텍스처 슬롯과 Slavic 캐릭터의 해석 불가능한 옛 재질 리맵 12개를 제거했다. EnergyExplosionHit의 방출이 꺼진 루트 렌더러에 있던 누락 재질 슬롯을 비웠다. 자식 파티클의 재질과 연출은 유지한다.

정리 전 파일은 `Logs/StaleReferenceBackup`에 보관했다. 원본 팩과 현재 프로젝트 백업은 `SourceAssets`에 있다.

텍스트 GUID 조사에는 데모 렌더러의 옛 Probe Volume 디버그 리소스 7개와 Harboria 재질의 옛 에디터 버전 기록 3개가 남는다. 현재 사용하는 게임 셰이더나 텍스처의 누락과는 구분하며, 이 기록 때문에 외형을 변경하지 않는다.

## 검증

- 소리 스캔 통합 및 잔광 테스트 2개 통과.
- 실제 걷기·앉기 발소리 음량 테스트 1개 통과.
- Windows 빌드와 입력 실행 결과는 아래에 기록한다.

- Windows 개발 빌드 성공: 오류 0, 경고 0, 약 277 MB. 위치: Builds/MouseFix/SoundThief.exe.
- 빌드 실행 검사 종료 코드 0: SoundConnection 재질 로드, 마우스 회전에 따른 시점 이동, 커서 잠금, 시작 씬 경비병 NavMesh 1/1 정상.
- 전체 스테이지의 수동 플레이나 파티클 외형 비교 검사는 이번 확인 범위에 포함하지 않았다.
