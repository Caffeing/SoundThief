# 길드 출구 수락 조건과 완료 문서 — 2026-10-30

길드 출구는 현재 의뢰를 수락해야 상호작용할 수 있다. 수락 전에는 조준 대상과 F 안내에서 제외하고, 직접 Interact를 호출해도 출발하지 않는다. 가장 가까운 문 충돌체가 선택 불가여도 뒤쪽 물체를 대신 선택하지 않는다. 수락 후에는 F로 출발한다. 기존 연습장 선택 이용과 HMM 의뢰 출발·복귀 흐름은 유지한다.

성공 시 MissionDirector는 완료한 스테이지 씬 경로를 현재 플레이 세션의 완료 이력으로 기록한다. 의뢰와 스테이지의 1:1 관계를 키로 사용한다. 길드로 돌아오면 현재 수락·아이템·운반 소리는 초기화하되 완료 이력은 남긴다. 테이블의 해당 문서에 초록색 **의뢰 완료**와 **완수한 의뢰** 설명을 표시하며 움직이는 문서도 같은 상태 표시 함수를 사용한다.

후속 사용자 결정에 따라 재수락 여부는 의뢰별 **재수락 불가능** 옵션으로 관리한다. 기본은 재수락 가능이며 현재 스테이지 1에는 재수락 불가능을 적용했다. 재수락 가능 의뢰를 다시 수락하면 문서에 **완료 · 재수락**을 표시한다. 설정과 최신 검증은 `contract-repeat-policy.md`를 따른다. 성공 이력만으로 출구를 다시 활성화하지 않는다. 준비 중 문서에는 완료를 표시하지 않으며, 목표물 취득만 하거나 실패·재시작한 것으로 새 완료 이력을 만들지 않는다.

완료 기록은 씬 전환과 문서 재열람을 넘어 현재 실행 세션에서 유지한다. 별도 디스크 저장·불러오기는 이번 범위에 포함하지 않았다. Unity의 새 Play 시작이나 게임 재실행은 새 세션이다.

## 변경

- ThiefInteractable.CanInteract: 길드 출구의 의뢰 수락 자격을 한곳에서 판정하고 실제 상호작용에도 적용.
- ThiefPlayer.FindTarget: 가장 가까운 충돌체를 고른 뒤 출구 자격 검사. 잠긴 문 뒤로 조준이 통과하지 않음.
- MissionDirector: 성공 이력을 현재 수락·완료 화면 상태와 분리해 씬 전환 후 보존.
- GuildContractOffer.IsCompleted / GuildContractView: 성공 이력을 해당 의뢰 문서의 설명·상태·색상에 반영.
- 길드 테스트의 세션 상태를 각 검사 시작에 초기화하여 완료 이력이 다른 검사에 이월되지 않게 함.

## 검증

- Unity 6000.3.19f1 컴파일 성공.
- 의뢰 테이블 검사 **11/11 통과**. 수락 전 실제 F 입력·직접 호출 차단, 수락 후 실제 F 출발, 성공 왕복 후 완료 문서·색상·재열람·재수락을 포함한다.
- 전체 PlayMode **71/71 통과**, 실패·건너뜀 0, 208.88초. 실패 재시작이 완료 이력을 만들지 않는 검사와 기존 소리·경비·저택 완주 회귀를 포함한다.
- 실제 Play에서 수락→저택→목표물 획득/탈출 처리→길드 문 귀환→문서 열람을 준비해 Game View를 캡처하고 완료 글자·색상·배치를 확인했다. 이 화면 검증 준비는 수동 키보드 완주를 뜻하지 않는다.
- 종료 후 길드 씬을 수정되지 않은 편집 상태로 열어 두었다. 스테이징·커밋·푸시는 하지 않았다.
