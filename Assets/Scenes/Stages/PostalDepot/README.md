# 우편 분류소 — 아직 보내지 마세요!

gganwoor 전용 그레이박스 스테이지. 기반은 main의 `9912e53` 공통 코어다. 공통 Runtime·Editor·Prefabs·SoundRules 및 다른 스테이지를 수정하지 않는다.

## 실행

Unity 6000.3.19f1에서 이 폴더의 `PostalDepot.unity`를 연다. 로컬 테스트용 `PostalDepot Local Playtest.asset` Build Profile이 이 씬만 포함하도록 설정돼 있다. 프로필을 활성화하고 Play를 누른다. 이 프로필은 macOS용이며 공용 `EditorBuildSettings`는 바꾸지 않는다. 다른 환경에서는 자기 플랫폼의 별도 프로필에 이 씬을 등록해야 재시작이 작동한다.

입력은 공통 코어 그대로다: WASD 이동, 마우스 시점, F 상호작용, E 추출, Q 주입, Ctrl 웅크리기, Tab 의뢰, Esc 일시정지, R 전체 재시작. **투척은 비활성화**다.

## 의뢰와 동선

홧김에 보낸 편지를 되찾아 달라는 가벼운 의뢰. 발송 직전이라는 상황 설정만 있고 실제 카운트다운은 없다.

1. 앞마당에서 접수실로 진입한다. 접수대 위의 직원 열쇠를 F로 획득한다.
2. 분류실 문에 접근해 E로 문·종 관계를 추출하고 F로 조용히 연다. 추출 중에는 기존 코어의 운반 속도·보유 제한을 따른다.
3. 분류 작업실의 날짜 도장이나 하역 통로의 종에 Q로 주입해 경비를 유인한다. 일단 주입하면 다시 다른 소리를 추출할 수 있다.
4. 작업대의 노란 분류표를 F로 확인한다. 목적지가 B구역이라는 안내가 나온다. 소지품의 ‘분류표 확인’은 확인 기록이며, 읽기 전용 UI가 생기면 교체할 임시 표현이다.
5. 발송 대기실 B구역에서 붉은 봉인 편지를 F로 회수한다. A/C구역에는 장식 소포만 있다.
6. 왔던 길 또는 오른쪽 하역 통로로 앞마당에 돌아와 청록색 출구에 F로 탈출한다.

분류표 확인과 편지 회수가 모두 완료 조건이다. 능력 사용 이력은 완료 조건으로 강제하지 않는다. 도중 경비와 접촉하면 공통 MissionDirector가 이 씬 전체를 다시 불러온다.

## 배치

전방(+Z) 순서: 앞마당 → 접수실 → 분류실 → 발송 대기실. 오른쪽(+X) 하역 통로는 접수실과 분류실, 발송실을 연결하는 우회로다. 첫 버전은 잠든 경비 2명, 소리 대상 4개, 종이 달린 문 1개로 구성한다. 경비의 소리·시야·패닉 규칙과 NavMesh 이동은 공통 코어를 그대로 사용한다.

공통 청각은 현재 벽을 무시하는 구현이다. 문·벽에 의한 청각 감쇠를 이 스테이지에서 임의로 새로 만들지 않는다. 이동 수레와 자동 분류기 같은 신규 기믹도 이번 버전에는 없다.

## 에셋 교체와 편집

- `01 Geometry`: 바닥·벽·책상·상자 등 기본 도형. Layer 8은 공통 시야/기절 차폐와 NavMesh용이다.
- `02 Postal props and signage`: 임시 구역 표지. 한글 임무/HUD는 기존 코어를 사용한다.
- 플레이어·문·열쇠·편지·소리 대상·경비·출구는 **공통 프리팹의 씬 인스턴스**다. 외형을 교체할 때 Collider·힌지·관계·출력·참조는 유지한다. 공통 원본에 Apply하지 않는다.
- `PostalDepot Definition.asset`: 스테이지 전용 의뢰와 아이템 ID. 다른 스테이지와 공유하지 않는다.
- 지형을 편집한 뒤 `01 Geometry`의 NavMeshSurface를 다시 Bake한다. 경비가 NavMesh 위에 있는지 확인한다.
- `PostalBriefing`은 분류표 힌트와 이 씬의 한글 글꼴 연결만 담당한다. 운영체제 글꼴을 참조하며 글꼴 파일을 복제/배포하지 않는다. 정식 배포용 글꼴은 별도 준비가 필요하다.
- `Sound Thief > Postal Depot > Create Or Open Graybox`는 기존 씬이 있으면 열기만 한다. 편집된 맵을 덮어쓰지 않는다.

## 검증과 남은 일

2026-10-29 전용 PlayMode 검사 **6/6 통과 (14.44초)**. 공통 참조·NavMesh 경로, 입구 통과/벽 충돌, 분류표 목적지 안내, 목표 두 개의 탈출 조건, 열쇠와 무음 개문·주입·원래 관계 복구, 의뢰 재시작 초기화를 확인했다. `Tests/PostalPlayModeTests.cs`와 `Docs/playmode-results.json`을 참조한다.

검사에서는 단계별 동작을 확인하기 위해 플레이어를 배치하고 일부 경비 업데이트를 멈춘다. 사람의 초회 완주 및 난이도 검증을 대신하지 않는다. 다음 검토는 우회로가 너무 쉬운지, 주입 유인이 유용한지, 표지와 목표물이 잘 보이는지다. 최종 아트·음향, 밸런스, 추가 고유 기믹은 후속 단계다.

이 작업은 로컬 구현이며 커밋·푸시하지 않았다.
