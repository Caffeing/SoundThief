# HMM 통합 적용 안내 (2026-10-30)

현재 이 폴더는 HMM의 **스테이지 3**으로 연결되어 있다. 아래 원본 README의 독립 실행/검증 기록보다 이 항목을 우선한다.

- 길드 세 번째 의뢰 수락 → 길드 출구 문 F → 우편국 수행 → 성공 후 길드 문 앞 복귀. startImmediately=false이며 전역 빌드 목록에 등록했다. macOS 전용 로컬 Build Profile로 전환할 필요가 없다.
- HMM 플레이어/경비/주입 대기/소리 전달/실제 음원/윤곽선/스캔을 사용한다. 독립 PostalDepot HMM Rules 자산을 사용하며 Stage2 전용 규칙을 변경하지 않는다.
- 편지와 하역문은 IThiefInteractionHandler로 HMM F 경로에 연결했다. PostalLetterReader는 F를 중복 수신하거나 매 F마다 플레이어 컴포넌트를 껐다 켜지 않는다. 편지 열람 중에만 플레이어를 잠그고 기존 전체 일시정지를 소유한다.
- 편지 네 통의 데이터·회수/교체·목표 ID·안쪽 하역문·원본 위치/NavMesh는 유지했다. 스테이지 3은 기본 재수락 가능이다.
- HMM 연결 재적용 메뉴: Sound Thief/Postal Depot/Connect To HMM. 원본 Apply Letter Search Layout은 배치와 본문을 재작성하고 NavMesh를 생성하므로 일상적인 연결 작업에 실행하지 않는다.
- 원본 테스트는 수동 수락·공통 F 경로·주입 지연에 맞춰 수정했다. 이번 통합은 컴파일만 확인하며 아래의 과거 PlayMode 통과 기록은 현재 HMM에 대한 결과가 아니다.

# 우편 분류소 — 아직 보내지 마세요!

gganwoor의 우편 스테이지 그레이박스. main의 공통 플레이어·소리·경비·아이템 코어를 사용한다. 이번 편지 탐색 기능은 이 폴더의 코드와 씬에만 추가했다. 공통 코드·프리팹·SoundRules·공용 빌드 씬 목록은 수정하지 않는다.

## 실행과 조작

Unity 6000.3.19f1에서 `PostalDepot.unity`를 열고 `PostalDepot Local Playtest.asset` 로컬 Build Profile을 활성화해 Play한다. 프로필은 macOS용이며 다른 플랫폼은 별도의 로컬 프로필에 씬을 등록한다.

- WASD 이동, 마우스 시점, F 상호작용, E 추출, Q 주입, Ctrl 웅크리기.
- Tab 의뢰, Esc 일시정지, R 재시작. 투척은 계속 비활성화다.
- 편지에 F: 내용 읽기. 읽기 창의 버튼 또는 Enter: 현재 편지 회수. 버튼 또는 Esc: 닫기.
- 읽는 동안에는 시간·경비·소리 보유 시간이 멈춘다. 창을 닫으면 조작과 시간이 복구된다. 읽기 창에서는 Enter/Esc와 버튼을 사용하고, 일반 조작은 닫은 뒤 사용한다.

## 의뢰와 찾기

의뢰인 바질은 로언에게 노란 우산을 돌려주지 않았다고 화내는 편지를 보냈다. 우산을 집에서 찾았으니 발송 전에 그 편지를 회수해 달라는 가벼운 의뢰다.

1. 접수실에서 직원 열쇠를 찾고 분류실 문의 소리를 추출한 뒤 F로 무음 개문한다. 오른쪽 하역문은 처음에는 닫혀 있고 바깥에서는 열리지 않는다. 분류실을 거쳐 하역 통로 안쪽에서 문에 F를 누르면 한 번 열려 계속 귀환 지름길로 쓸 수 있다. 접수실에서 하역 통로로 빠지는 연결부도 막혀 있다. 재시작하면 하역문이 다시 닫힌다.
2. 분류표를 확인하면 개인 편지가 발송 대기실 A~C 선반에 있다는 안내가 나온다. 정확한 편지나 선반 번호는 알려주지 않는다.
3. 발송실의 선반은 앞뒤 2열, 총 6개다. 쌓인 우편물 대부분은 장식이며 F 안내가 표시되는 편지 4통을 읽을 수 있다.
4. 각 편지는 수취인·발신인·내용이 다르다. 이름이나 ‘우산’이라는 단어만으로 결정하지 말고 의뢰의 사연과 대조한다. 읽기만 해서는 소지품이 바뀌지 않는다.
5. 회수 가능한 편지는 한 통이다. 다른 편지를 회수하면 기존 편지를 교체한다. 편지 오브젝트는 남아 있으므로 다시 읽고 바꿀 수 있다. 오답을 고르는 것만으로 벌이나 재시작은 발생하지 않는다.
6. 분류표 확인 기록과 의뢰에 맞는 편지가 있어야 앞마당 출구 F로 완료된다. 오답 편지로는 탈출이 거절된다.

목표 선반도 다른 선반과 같은 개방형 배치다. 목표만 감싸는 칸막이나 앞을 막는 경비는 없다. 앞줄 선반은 모두 z=20에 나란히 놓인다. 발송실 경비와 소리 장치는 동쪽 하역 구역에 있으며 특정 편지의 정답 위치를 가리키지 않는다. 잠든 경비와 접촉해도 재시작되지만, 편지 탐색에 소리 유인을 강제하지 않는다.

## 공간 확장 (2026-10-30)

바닥은 16×32m에서 24×38m로 확장했다(512→912㎡, 약 1.78배). 접수실·분류실의 서쪽 벽과 하역 구역 외벽을 함께 늘려 방 사이에 빈틈이 생기지 않도록 했다. 하역 팔레트를 동쪽 벽으로 옮겨 귀환 통로를 넓혔다.

발송실의 좌우 선반은 x=-7/7, 뒤쪽 선반은 z=29로 재배치해 중앙과 뒤쪽을 순환할 수 있다. 선반은 6개, 읽는 편지는 4통 그대로다. 벽 쪽에 작업대·우편 운반대·소포 더미를 추가했다. B 선반 칸막이는 후속 개선에서 모두 제거했고, 발송실 경비는 동쪽 하역 구역으로 옮겼다. 소리 원천과 주입 우편함도 같은 하역 구역에 배치했다. 넓은 맵 때문에 소리 운반 난도가 올라가지 않도록 한 조정이다.

## 구현과 편집

- `PostalLoadingGate`: 우편국 F 처리에서 안쪽 위치를 확인한 뒤 하역 셔터와 충돌·NavMesh 장애물을 해제한다. 공통 문 코드는 수정하지 않는다.
- `PostalLetter`: 편지별 ID, 수취인, 발신인, 본문, 목표 여부를 Inspector에서 편집한다. 읽은 상태는 실행 중에만 유지된다.
- `PostalLetterReader`: 우편 씬의 F 입력을 먼저 처리해 편지가 즉시 수집되지 않도록 한다. 다른 대상은 기존 `ThiefInteractable.Interact`로 위임한다. F 처리 프레임에는 공통 플레이어 입력을 잠시 중단하고 프레임 끝에 복구하며, 읽는 동안은 기존 MissionDirector 일시정지를 소유한다.
- 읽기 창은 런타임 uGUI Canvas로 생성된다. 기본 도형과 임시 색만 사용하고, 공통 HUD·프리팹 원본에 Apply하지 않는다.
- `PostalBriefing`: 분류표 안내와 OS 한글 글꼴 연결을 담당한다. 글꼴 파일은 복제하거나 배포하지 않으므로 정식 배포용 글꼴은 후속 준비가 필요하다.
- `PostalSearchAuthoring.Apply Letter Search Layout`: 해당 씬의 확장 배치·선반·편지 기본 본문을 다시 적용하고 NavMesh를 갱신한다. 실행하면 이 기능의 배치와 편지 내용이 기본값으로 다시 작성된다. 수동 편집한 뒤에는 필요할 때만 실행한다.
- `Create Or Open Graybox`는 기존 씬이 있으면 열기만 한다. 새로 생성할 때는 편지 탐색 배치를 함께 적용한다.
- 정답 위치는 고정이다. 현재 `Letter B`의 편지 #03이 목표이며, #01/#02/#04는 내용을 대조하기 위한 후보다. 이 정보는 제작·검증용이며 읽기 창에 정답 표시는 하지 않는다.

## 검증

2026-10-30 전체 PlayMode 검사 51/51 통과, 그중 우편 검사 12/12 통과. 기존 검사에 서로 다른 본문·읽기와 수집의 분리·오답 교체·오답 탈출 거절·읽기 중 타이머 정지와 조작 복구·벽 차폐 검사를 포함한다.

실제 키보드/마우스 입력으로 네 편지 읽기, 마우스 회수 버튼, Esc 닫기, 오답 탈출 거절, 소리 보유 중 읽기, 정답으로 교체 후 탈출까지 확인했다. 알려진 맵을 자동 조향한 검사이므로 사람의 초회 탐색과 재미 검토는 별도로 필요하다. 상세 로그·화면·최종 전체 검사 결과는 저장소 바깥 `work/postal-letter-search-2026-10-30/`에 보존한다.

커밋과 푸시는 사용자가 진행한다.

공간 확장 후 재검증: 전체 PlayMode 52/52(우편 13/13) 통과. 새 선반 순환 통로와 귀환 경로의 NavMesh 연결, 실제 입력으로 네 편지 읽기·소리 추출/주입·정답 교체·탈출까지 확인했다. 자동 조향은 정답과 동선을 알고 진행하므로 초회 난이도 평가는 별도다. 증거는 저장소 밖 `work/postal-expansion-2026-10-30/`에 보존한다.

하역문 수정 후 우편국 PlayMode 15/15 통과: 외부 F 개방 거절·충돌 유지, 내부 F 개방 후 양방향 통과, 재시작 초기화, 접수실 옆 우회 차단, 기존 편지·소리·탈출 검증 포함. 실제 입력으로 열쇠·무음 개문·안쪽 해제·양방향 통과도 확인했다. 이번 전체 검사는 240초 제한으로 완료되지 않았으며, 우편국 검사만 분리 재실행해 통과했다.

## 편지 분위기와 이름 개선

한국식 인명 대신 가상 인명을 사용한다. 의뢰 메모·StageDefinition·편지 본문을 함께 변경했다.

- #01 피파 → 올리버: 발랄한 빵집 시식회 초대. 딸기 타르트와 새 빵 이름 짓기.
- #02 바넌 공방 → 셀레스트: 정중하고 건조한 망원경 부품 배송 안내.
- #03 바질 → 로언: 노란 우산을 돌려달라는 심통 섞인 항의. 회수 대상.
- #04 마일로 → 루카: 갈매기에게 점심을 빼앗긴 선장의 과장된 무용담.

네 편지의 발신인·수취인·주제·말투를 각각 구분하며 정답 선반에는 별도 외형 표식을 두지 않는다. 봉투와 선반 크기는 동일하다.

선반·편지 개선 후 우편국 PlayMode 15/15 통과. 목표 칸막이 제거·앞줄 선반 정렬·경비 거리와 발신인/수취인 구분을 기존 편지 읽기·회수·교체·탈출·재시작 검사와 함께 확인했다.
