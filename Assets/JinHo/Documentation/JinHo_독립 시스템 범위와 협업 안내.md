# JinHo 독립 시스템 범위와 협업 안내

현재 기준: 2026-10-30. 이 파일은 AGENTS.md가 연결하는 공용 안내의 정본이다. 이전 설명과 조사 원본은 로컬 백업으로 보존했으며, 그 안의 과거 수치나 계획을 현재 지시로 적용하지 않는다.

## 변경 권한과 보호 범위

- JinHo 기능에만 한정된 독립 구현 예외가 있다. 공통 시스템 전체의 변경 승인이 아니다.
- 기준 `Assets/Scenes/ManorPrototype.unity`, 공유 프리팹·규칙 자산과 Player·카메라·입력·이동·HUD·인벤토리·미션의 기존 컴포넌트 및 참조 타입을 보호한다. 이 영역의 사본·대체는 승인되지 않았다.
- 새 런타임·씬·구현 자산은 `Assets/JinHo/`, 협업·설명 문서는 `Assets/JinHo/Documentation/`에 둔다.
- 사용자 승인된 공통 연결부는 `Assets/SoundThief/Runtime/SoundWorld.cs`와 `GuardAgent.cs`다. 2026-10-30 추가 승인으로 `SoundEmitter.cs`의 선택적 주입 지연 설정도 포함한다(기본 3초, Stage2만 0초). 선택적 소리 전달/음량 정책, 각성 설정, 선택적 조사 체류 정책을 제공한다. 정책 미연결/각성 설정 기본 false인 기존 씬은 원래 흐름을 사용한다.
- 새 순찰·방 확인 동선은 없다. 원본 소리 조사·추적·복귀를 사용한다. 비공개 상태 강제 변경, 런타임 패치, 가짜 소리, 매 프레임 상태 덮어쓰기를 추가하지 않는다.
- 공통 담당자가 별도 승인받은 작업은 그 권한에 따르되 JinHo 연결 영향을 조사한다. 이 문서를 다른 담당자의 작업 전체에 대한 수정 금지로 확대하지 않는다.
- 다른 채팅·메신저에 전달하거나 원격 저장소로 push하는 것은 별도 명시적 지시 없이 수행하지 않는다.

## 현재 구현과 남은 문제

현재 스테이지는 `Assets/JinHo/Scenes/JinHo.unity`다. Player/HUD/미션과 기존 연결 타입을 재사용하고 JinHo 전용 소리 전달·경비 체류 정책을 연결한다. 자세한 파일·호출 흐름은 [구현 설명](JinHo_구현설명.md)을 따른다.

유인1의 **추가 유지 시간은 2초**다. 소리 출력 종료부터 계산하며, 전신 입장 후 정확히 2초 체류하는 구현이 아니다. 원본 출력 8초와 경계 4초는 유지한다. 유인2는 전신 입장 후 최소 3초와 G2→G1 역순 퇴장 정책을 유지한다.

거울의 목적은 플레이어가 **문3에 가기 전에 경비2의 존재를 확인**하는 것이다. 경비가 플레이어를 발견하게 하는 기능이 아니다. 사용자는 직접 플레이에서 앞서 보고한 거울 차폐와 유인2 발견 문제가 없다고 확인했다. 과거 준비된 관찰점의 자동 검사 실패와 사용자 확인을 구분하며, 현재 플레이에 재현되는 결함으로 단정하지 않는다.

사용자가 추가로 보고한 것은 거울 앞에서 자기 모습이 보이지 않는 현상이다. 현재 PlayerRig 아래에는 카메라만 있고 몸을 표시하는 Renderer가 없다. 따라서 반사할 몸 모델이 없는 상태이며, 기존 Player 외형을 숨기는 코드가 원인으로 확인된 것은 아니다. 이번 조사에서는 몸 모델/대체 표현을 새로 만들거나 Player·카메라 구성을 변경하지 않았다.

최신 검사는 공통 38/38 통과, JinHo 2/4 통과였다. 이후 유인1 2초 변경은 사용자 지시로 테스트하지 않았다. 상세 경계와 합격 조건은 [요구사항과 검증](JinHo_요구사항과검증.md)을 따른다. 과거 배치의 통과 기록으로 현재 맵 전체 합격을 대신하지 않는다.

## 자료와 협업 기록

공간 연결의 기준은 설계 폴더의 `스테이지 1 맵 평면도_2026-10-29.png`와 같은 이름의 SVG다. 원본은 외부 설계 자료이며 저장소에 포함되지 않는다. 위키와 GitHub 위키를 기준으로 대체하지 않는다. 문서는 과거 발언 기록과 최신 확정을 구분하며 B1/B1.1 치수·좌표·시간 제안은 검증된 결과로 취급하지 않는다.

작업 시작 시 이 문서와 관련 구현을 읽고 현재 협업자에게 영향 범위·보호 조건·검증 상태를 알린다. 맵을 변경할 때 원본 평면도와 대조하고 차이를 기록한다. 상충하는 최신 확정이 있으면 정확한 문장·파일·영향을 제시한다.

작업 종료 시 실제 변경·보존 여부·검증/미검증을 보고하고 이 문서를 갱신한다. 파일이 있다는 이유만으로 다른 AI가 읽었거나 다른 작업 사본에 전달됐다고 간주하지 않는다.
