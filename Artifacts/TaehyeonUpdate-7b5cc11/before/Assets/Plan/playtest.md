# 공통 스테이지 기반 실행 안내

현재 개발 목표는 공통 기반이다. 제작 방법은 stage-authoring.md를 따른다.

Assets/Scenes/Stages/FrameworkExample.unity를 열어 Play한다. 구리 열쇠를 F로 얻고 문을 열어 두 유물을 모두 회수한 뒤 시작 위치 뒤의 출구에서 F로 완료한다. R로 같은 씬의 전체 상태를 초기화한다. 기존 ManorPrototype도 직접 실행하면 의뢰가 시작된다.

길드와 훈련장은 다른 팀원 담당이다. 기존 길드 프로토타입과 전용 기획서는 삭제했다.

## 의뢰 플레이

1. 시작 지점 왼쪽 받침대 위의 작은 금색 열쇠를 조준하고 F로 획득한다.
2. 정면의 잠긴 문 가까이 가서 E로 `열쇠 ↔ 자물쇠` 관계를 추출한다. 청록 연결과 무음 표시, 보유 타이머를 확인한다.
3. F로 문을 연다. 문 통과 시에도 무음 관계와 보유 타이머는 유지된다.
4. 문 너머 왼쪽의 청록색 공명체를 조준하고 Q로 주입한다. 손이 비워지고 정상 속도로 이동한다. 경비가 반복되는 소리를 듣고 깨어나는 것을 관찰한다.
5. 기둥과 가림막을 이용해 저택 안쪽의 금색 인장을 F로 챙긴다.
6. 시작 지점 뒤편의 청록색 출구 표식을 조준하고 F로 탈출한다. 목표물 없이 출구를 사용하면 성공하지 않는다.

## 조작

| 입력 | 기능 |
| --- | --- |
| WASD / 마우스 | 이동 / 시점 |
| F | 일반 상호작용 |
| E / Q | 관계 소리 추출 / 조준한 공명체에 주입 |
| 마우스 왼쪽 | 투척 개발 보류·비활성 |
| 왼쪽 Ctrl | 웅크리기. 소리 보유 중에는 자동으로 느린 이동 |
| Tab | 의뢰 확인. 게임 시간은 계속 흐름 |
| Esc | 일시정지 / 계속 |
| R | 현재 스테이지 전체 초기화 |

## 추가 실험

- 소리를 들고 기다려 자기 위치 폭발·기절·원래 관계 복구를 확인한다. 폭발 자체로 실패하지 않는다.
- [개발 보류·현재 실험 제외] 좌클릭으로 소리를 던진 뒤 즉시 정상 속도로 움직이고 다른 관계를 추출한다. 원래 관계는 투척 시점이 아니라 폭발 시점에 복구된다.
- 첫 공명체 출력 중 다른 공명체에서 추출·주입한다. 여러 대상 출력은 가능하고 이미 출력 중인 같은 대상에 대한 주입은 거절된다.
- 경비 표시는 수면 `zzz`, 인식 추적 `!!`, 고정 위치 확인 `!`, 경계 `?`, 기절 `×`, 회복 후 `패닉 · 면역`이다. 경비와 접촉하면 의뢰가 즉시 처음부터 시작된다.

## 현재 범위

외부 미술 없이 기본 도형과 임시 합성 음향으로 만든 규칙 검증용 3D 씬이다. 정식 중세 저택 미술, 손·시전 애니메이션, 투척 궤적 미리보기, 경비 반응 범위 예측, 공간별 소리 감쇠, 후속 의뢰와 저장 매개체는 후속 작업이다. 벽은 일반 청각을 차단하지 않으며 시야와 폭발 기절을 차단한다. 수면 중 시야는 비활성이라는 임시 설계를 적용한다.

자동 검사: Unity Test Runner에서 PlayMode의 `SoundThief.Tests`를 실행한다. 공통 기반 검증은 `framework-verification.md`, 투척 비활성화 검증은 `sound-ai-decisions.md`, 기존 저택 검증 이력은 `verification.md`에 기록한다.
