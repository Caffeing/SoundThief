# 길드와 연습장

## 길드

길드는 플레이어가 의뢰를 받는 거점이다. 길드 안에 소리 능력을 시험하는 연습장을 둔다. 기존 튜토리얼 일부는 연습장으로 옮기고 기존 저택은 [[06 스테이지 1|스테이지 1 — 중세 대저택]]으로 사용한다.

게임은 **3D 1인칭**이다. 연습장도 의뢰 스테이지와 같은 시점·대상 선택·능력 규칙을 사용한다. 길드의 NPC·정식 외형은 후속으로 정한다. 의뢰는 테이블 위 문서 묶음에서 확인하고 수락한다.

## 현재 개발 범위 — 길드·튜토리얼·출발

**길드와 연습장은 하나의 Unity 씬에 배치한다.** 둘 사이의 이동은 같은 씬 안에서 이루어지며 별도 씬 로딩으로 나누지 않는다.

현재 우선 구현할 것은 길드 공간과 그 안에서의 **3D 1인칭 이동·마우스 시점 조작**이다. 의뢰 수락 전에도 이동할 수 있어야 하며, 의뢰의 수락 여부를 길드 이동의 조건으로 사용하지 않는다. 바닥·벽 등 기본 충돌을 갖춰 공간을 돌아다닐 수 있도록 한다.

현재 의뢰는 **스테이지 1·2·3에 대응하는 세 개**를 제공한다. 길드의 출구로 향하는 동선에서 좌측 또는 우측 연습장으로 선택적으로 들어갈 수 있게 배치한다. 길드 이동을 기반으로 의뢰 수락, 연습장 튜토리얼, 길드 출구 문 상호작용에 의한 출발을 연결한다. 스테이지 성공 후 길드 출입문 안쪽으로 복귀한다. 스테이지 2 의뢰를 추가했으며 별도 해금·보상은 후속 범위다.

## 진행 구조

**의뢰 테이블 F → 문서 확인·수락 → ESC로 테이블 종료 → 출구로 직접 이동하거나 연습장 선택 이용 → 출구 문 F → 스테이지 1 수행·절도 후 탈출 → 길드 출입문 복귀**으로 진행한다. 의뢰를 수락하는 순간에는 씬을 바꾸지 않는다. 출구에 접근하는 것만으로도 출발하지 않는다.

**연습장과 그 안의 튜토리얼은 선택사항**이다. 의뢰를 수락한 뒤 바로 출구로 가도 되고, 좌측 또는 우측에 배치된 연습장에 들러 현재 사용 가능한 기술을 연습한 뒤 출발해도 된다.

출발 조건은 **의뢰 수락 + 출구 문 상호작용**뿐이다. 연습 여부·학습 진행·튜토리얼 완료를 출발 조건으로 검사하거나 출발을 막는 데 사용하지 않는다. 연습장을 이용하지 않아도 같은 스테이지 1에 진입한다.

의뢰와 스테이지의 1:1 관계는 유지하고 연습장은 별도 의뢰로 세지 않는다. 실제 수행 가능한 의뢰는 스테이지 1·2·3의 세 개다. 실패는 해당 스테이지 전체 재시작이며 성공 때만 길드로 복귀한다.

## 의뢰 테이블과 문서 넘김

- 테이블 위에 여러 종이를 놓고 **테이블에 F로 상호작용**하면 문서 열람 상태에 들어간다. 기존 세로 게시판을 대체한다.
- 한 번에 의뢰 하나의 문서와 그 의뢰의 간략한 설명만 표시한다. **←는 맨 앞 문서를 왼쪽으로 빼서 묶음 뒤에 넣고, →는 맨 뒤 문서를 왼쪽 옆으로 꺼내 앞에 덮는다.** 책장처럼 접어 뒤집지 않는다. 종이 본문·제목을 유지한 채 들어 올림·옆 이동·앞뒤 겹침 교체·안착을 부드럽게 이어 준다. 문서 묶음을 순환하므로 첫 문서에서도 양쪽 입력이 가능하다. 문서가 하나면 이동하지 않는다. 전환 중 연속 입력·중복 수락은 계속 차단한다.
- 열람 중 이동·마우스 시점·소리 능력·재시작을 차단한다. **ESC는 테이블 열람만 종료**하고 즉시 일시정지하지 않는다. 테이블 밖에서 ESC를 누르면 기존 일시정지를 사용한다.
- 열람 상태의 F 또는 Enter로 현재 문서를 수락한다. 수락 직후에도 문서 화면과 길드를 유지한다. ESC로 닫은 뒤 직접 출구까지 이동해야 출발한다.
- 수행 가능한 의뢰만 수락한다. 이미 수락한 의뢰는 다른 문서를 넘기거나 테이블을 닫아도 유지한다. 준비 중 문서나 연습 완료로 목적지를 바꾸지 않는다. 길드에서 Tab/Enter만으로 테이블을 원격으로 열거나 수락하지 않는다.
- 문서 열람은 월드 일시정지가 아니다. 보유 소리 시간·출력·경비 시간은 계속 흐른다. 보유 소리가 만료되어 기절하면 문서 열람도 종료한다.
- 새 의뢰는 `GuildContractTable.offers`에 StageDefinition·대상 씬·수락 가능 여부를 연결한다. 공개되지 않은 문서는 정식 스테이지로 취급하지 않는다.

## 성공 후 길드 복귀

스테이지 1에서 목표물을 훔친 뒤 출구에 F로 상호작용해야 성공한다. 성공 안내 뒤 자동으로 길드 씬을 로드한다. **스폰 지점은 테이블이 아니라 출입문 안쪽의 `Guild return spawn`**이다. 실내를 바라보며 다시 이동할 수 있어야 한다. 출구에 닿았다는 이유만으로 즉시 재출발하지 않는다.

복귀는 새 길드 상태로 시작한다. 완료한 의뢰 수락 상태·실전 아이템·보유 소리·기절·문서 열람·일시정지를 이월하지 않는다. 완료 이력은 현재 플레이 세션에서 유지하며 스테이지 1은 재수락 불가, 스테이지 2·3은 재수락 가능이다. 영구 완료 목록·보상 저장은 구현하지 않는다. 실패/재시도는 길드로 보내지 않고 수락 상태를 유지한 채 해당 스테이지를 완전 초기화한다.

## 최초 학습과 새 능력 연습

연습장은 일회성 튜토리얼 전용 구역이 아니라 **능력을 얻을 때마다 다시 이용하는 상시 연습 공간**이다. 처음 이용할 때는 기본 조작과 현재 능력을 배우는 튜토리얼로 사용하고, 이후 새 능력을 얻으면 다음 의뢰를 수행하기 전에 그 능력을 먼저 시험할 수 있게 한다.

능력을 획득한 상태와 연습한 상태는 구분한다. 연습장을 이용했다고 능력을 자동 획득하는 구조로 정하지 않으며, 실제 획득한 능력에 대응하는 설명·연습 대상을 제공한다. 새 능력의 종류·획득 방식과 구체적인 연습 구성은 후속 기획으로 남긴다.

첫 학습과 새 능력 연습 모두 **선택사항**이다. 연습장을 건너뛰거나 충분히 연습하지 않았다는 이유로 의뢰 출발을 막지 않는다. 현재 의뢰 세 개·스테이지 1·2·3 구조를 사용하며, 새 능력 추가 시에도 같은 연습장 구조를 확장한다.

## 선택형 연습·튜토리얼

| 연습 | 내용 |
| --- | --- |
| 기본 조작 | 1인칭 이동·마우스 시점·조준·상호작용 |
| 추출·운반 | 두 매개체 연결·관계 무음·등급·느린 이동·보유 시간 |
| 주입 | 지정 대상 출력·감쇠·원래 관계 복구 |
| 연속 사용 | 사용 후 재추출·다른 대상 동시 출력·동일 대상 중첩 금지 |
| 투척 | 개발 보류·현재 비활성. 재개 시 기존 설계와 보존 검사를 검토 |
| 위험·AI 반응 | 시간 초과·기절·벽에 막히는 기절 범위·회복 후 패닉 |

튜토리얼은 현재 사용 가능한 조작·추출·운반·주입을 연습장에서 다룬다. 투척은 현재 비활성으로 필수 실습이나 조작 안내에 넣지 않는다. 위 표는 세부 실습 구성안이며, 경비 패닉이나 시간 초과 위험의 안내·직접 실습 범위는 제작하면서 정한다. 학습 안내의 진행 여부는 출발과 무관하다. 강제 자폭을 요구하는 것으로 확정하지 않는다. AI 관찰용 대상을 실제 경비로 둘지 대체 장치로 둘지는 제작하면서 정한다.

## 연습 상태와 초기화

소리 등급·보유 제한·감쇠·투척·기절 등은 실전과 같은 시스템을 사용한다. 연습하기 쉽도록 대상과 상태를 다시 준비하는 기능을 제공하는 방향으로 설계한다. 시간 제한 해제나 기절 면역을 임의로 추가하지 않는다.

연습 초기화는 연습장의 관계·운반·출력·투척물·대상 상태를 정리하고 실제 의뢰 진행과 분리해야 한다. 연습을 다시 시작하거나 끝내도 실제 능력 획득 상태를 변경하지 않는다. 초기화 받침대 F 또는 연습장 밖 로비 복귀 시 연습 상태를 정리하며 수락한 의뢰는 유지한다. 실전으로 연습 소리를 이월하지 않는다.

## 2026-10-30 출구 활성화와 의뢰 완료 표시

스테이지 1 의뢰를 수락하기 전에는 길드 출구 문을 상호작용 대상으로 선택할 수 없으며 조준 F 안내도 표시하지 않는다. 수락 후에는 출구 문이 상호작용 가능해지고 F로 스테이지에 출발한다. 연습장 이용·튜토리얼 완료는 출발 조건이 아니다.

목표물 회수와 탈출을 모두 완료하면 해당 의뢰의 완료 이력을 기록한다. 길드 출입문으로 돌아온 뒤 테이블 F로 문서를 열면 초록색 **의뢰 완료** 표시와 **완수한 의뢰** 설명을 보여 준다. 준비 중 문서에는 완료를 표시하지 않는다. 문서를 닫았다 다시 열어도 완료 표시는 유지된다.

완료 이력과 현재 수락 상태는 별개다. 귀환하면 수락·실전 아이템·소리는 초기화되고 출구는 다시 비활성화된다. 완료한 의뢰의 재수락은 의뢰별 인스펙터 옵션으로 관리한다. 기본은 재수락 가능이며 **재수락 불가능**을 켜면 완료 후 다시 수락할 수 없다. 현재 스테이지 1 의뢰는 재수락 불가능으로 설정했다. 실패·재시작이나 목표물 획득만으로 완료 이력을 새로 만들지 않는다.

현재 완료 기록은 실행 중인 플레이 세션에서 씬 전환을 넘어 유지한다. 게임 종료 후 재실행 또는 Unity의 새 Play 시작에 대한 디스크 저장 기능은 이번 범위에 추가하지 않았다. 상세 구현·검증은 Unity 프로젝트의 `Assets/Plan/guild-contract-progress.md`를 따른다.


## 의뢰별 재수락 설정

Unity의 `Guild.unity`에서 **Contract table → GuildContractTable → Offers → 해당 의뢰 → 재수락 불가능**을 설정한다.

| 설정 | 완료 후 동작 |
| --- | --- |
| 끔 — 기본값 | 재수락 가능 |
| 켬 | 재수락 불가능 |

현재 스테이지 1 「푸른 저택의 인장」에는 이 옵션을 켰다. 최초 수락과 실패 후 재시도는 막지 않는다. 완료 후 문서에는 **의뢰 완료 / 재수락 불가능**을 표시하고 F·Enter 수락을 차단한다. 수락이 없으므로 길드 출구도 활성화되지 않는다. 새 의뢰의 기본값은 옵션 꺼짐이며 의뢰마다 따로 설정할 수 있다. 완료 기록의 현재 플레이 세션 범위는 기존과 같다.


2026-10-30 스테이지 2 통합: 길드에서 「푸른 저택의 인장」과 「두 경비의 보관실」을 선택할 수 있다. 스테이지 1은 재수락 불가, 스테이지 2는 기본 재수락 가능이다. 길드·스테이지 1·2에 이동 발소리 원음을 연결했다. 신규 스테이지와 확인 범위는 [[14 스테이지 2]]를 따른다.

2026-10-30 우편국 의뢰 추가: 세 번째 문서 「아직 보내지 마세요!」와 스테이지 3을 연결했다. 편지 읽기·정답 회수·안쪽 하역문과 HMM 공통 시스템을 사용한다. 상세와 컴파일 확인 범위는 [[15 스테이지 3]]를 따른다.
