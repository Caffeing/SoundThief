# 스테이지 3 — 우편 분류소

gganwoor의 「아직 보내지 마세요!」 의뢰를 HMM에 통합했다. 원본 공간·선반·편지·경비 위치와 구운 NavMesh를 유지하며 HMM 공통 플레이어·소리·경비 시스템을 사용한다.

- 길드 테이블의 세 번째 의뢰로 수락한다. 수락 직후 이동하지 않고 출구 문 F로 출발하며, 성공 후 기존 길드 문 앞 복귀 위치로 돌아온다.
- 스테이지 1은 재수락 불가를 유지한다. 스테이지 2·3은 기본 재수락 가능이다. 완료 표시는 기존 길드 시스템을 사용한다.
- 접수실의 직원 열쇠 → 분류실 문 → 분류표 → 발송실 편지 탐색 → 앞마당 탈출로 진행한다. 하역문은 안쪽에서 해제하면 귀환 지름길이 된다.
- 읽을 수 있는 편지 네 통의 수취인·발신인·본문을 의뢰 사연과 대조한다. F는 읽기, Enter/버튼은 회수, ESC/버튼은 닫기다.
- 읽기만으로 회수하지 않는다. 한 통만 선택하며 다른 편지로 교체할 수 있다. 분류표 기록과 올바른 편지가 모두 있어야 성공한다. 오답 선택 자체로 실패하지 않는다.
- 편지 열람 중 이동·시점 입력과 세계 시간을 멈추는 원본 규칙을 유지한다. 경비와 소리 보유 타이머도 멈춘다. 일반 Tab 의뢰창과 길드 테이블의 시간 진행 규칙은 바꾸지 않는다.
- 주입은 HMM 기본 대기 뒤 출력한다. 스테이지 2의 즉시 주입 및 별도 규칙은 변경하지 않는다.
- HMM의 실제 웅크리기, 미세 이동 보정, 플레이어·경비 발소리, 경비 외형과 시야 표시, 조준 윤곽선, 소리 스캔을 연결했다. 투척 허용 여부 등은 독립된 우편 HMM 규칙 자산으로 관리한다.

씬: `Assets/Scenes/Stages/PostalDepot/PostalDepot.unity`.
규칙: `Assets/Scenes/Stages/PostalDepot/PostalDepot HMM Rules.asset`.
의뢰 정의의 stageId는 기존 제작 도구와 호환되도록 `gganwoor-postal-depot`를 유지한다.

코드 컴파일만 확인하며 이번 통합의 Play Mode/실제 동선/편지 읽기/성공 복귀 실행 검증은 수행하지 않는다. 원본 브랜치의 과거 검증 결과를 현재 HMM 검증 결과로 보지 않는다.
