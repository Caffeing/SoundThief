# 스테이지 2 — 두 경비의 보관실

JinHo 브랜치의 맵을 `Assets/Scenes/Stages/Stage2/Stage2.unity`로 저장하고 현재 HMM 플레이어·입력·이동·NPC AI·소리·HUD·의뢰 시스템을 사용하도록 연결했다. 벽·문·오브젝트 배치와 크기는 원본 그대로 유지한다. 원본 JinHo 씬은 참고용으로 보존하며 실제 길드 의뢰는 Stage2 씬을 사용한다.

길드 문서의 **두 경비의 보관실**을 수락하고 출구 F로 출발한다. 목표 인장을 회수한 뒤 출구로 탈출하면 길드 문으로 복귀하고 해당 의뢰의 완료 이력을 표시한다. 스테이지 2는 기본 재수락 가능이며 스테이지 1은 재수락 불가능을 유지한다. 별도 선행 의뢰 완료 조건은 추가하지 않았다.

방·통로 그래프 기반 청각/음량 정책, G1의 최초 각성 후 각성 유지와 G2의 각성 대기, 유인방 체류·전신 입장·역순 퇴장 정책, 거울 관찰을 JinHo에서 가져왔다. 기존 HMM 벽 감쇠와 중복 적용하지 않으며 소리 스캔도 같은 전달 정책을 사용한다. NPC의 이동·시야·추적·문 통과·회전·기절·패닉은 HMM GuardAgent가 수행한다.

길드와 스테이지 1·2의 플레이어에 taehyeon 이동 거리 기반 발소리를 연결했다. 걷기·운반·웅크리기의 피드백 음량은 기존 taehyeon 방식을 사용한다. 발소리는 청취/스캔 피드백이며 경비에게 조사 자극을 추가하는 Pulse로 바꾸지 않았다.

스테이지 2 전용 의뢰 정의·HMM 규칙 복제·이동망 복사본을 사용한다. 맵과 이동망을 다시 생성하거나 굽지 않았다. 주입 지연과 추격 등은 현재 HMM 기준이므로 과거 JinHo의 정확한 동선·타이밍이 같다고 가정하지 않는다.

현재 작업에서는 사용자 요청에 따라 **플레이·자동 테스트·완주·실청·렌더링 검증을 하지 않고 컴파일만 확인**한다. 지도 보존은 저장된 파일의 공간 속성 비교로 확인했다. 자세한 구현과 변경 근거는 Unity 프로젝트 `Assets/Plan/stage2-integration.md`를 따른다.


## 스테이지 1 스타일 외형 적용 (2026-10-30)

스테이지 1과 같은 석벽·석판 바닥·목재 천장/보·목제 문·문틀·가구·랜턴 스타일을 적용했다. 원래 동선·문 회전축·아이템 위치·충돌체·NavMesh와 의뢰/퍼즐 규칙은 유지한다. 스테이지 2의 관찰 틈/거울과 스테이지 3의 편지 네 통/안쪽 하역문도 유지한다. 실행 검증 없이 컴파일만 확인하며, 외형 적용 도구는 `Assets/Game/Editor/StageManorVisuals.cs`다.
